# PAL Mexico Cash vs. In-Kind Replication in R

This repository contains an R implementation of the original PAL Mexico cash-versus-in-kind replication workflow used in the Cunha–De Giorgi–Jayachandran project.

The goal is to reproduce the authors' workflow from the same level of source data used by the original Stata scripts, while keeping the R repository clean, auditable, and reproducible.

## Replication status

The replication is substantially successful.

The following components reproduce the original results closely or exactly:

- baseline household means, including non-food expenditure after correcting its construction;
- the no-controls aggregate consumption regressions;
- food, in-kind, and non-in-kind treatment effects in the main consumption analysis;
- most class-attendance variables;
- the main sample, treatment coding, household-wave structure, and locality structure.

Several differences remain and are documented in `REPLICATION_SUMMARY.md` rather than being further revised:

- `n_class_noORG` is still duplicated from `n_class` in the R output;
- the controlled aggregate consumption specification does not fully reproduce the original `exp_total` and `exp_nfood` coefficients and standard errors;
- the robust controlled specification inherits the same issue;
- the disaggregated consumption output contains 26 goods rather than the original 30, omitting four meat/fish categories;
- some output scope and figure definitions differ from the original Stata package.

These remaining differences should be treated as known replication limitations.

## Data-handling principle

The original workflow begins from raw survey data and performs the cleaning and construction steps before analysis. Therefore this repository also begins from raw inputs.

Required source data belong under:

```text
data/source/raw/
```

R-generated intermediate data belong under:

```text
data/intermediate/
```

Final analysis-ready datasets belong under:

```text
data/processed/
```

Author-generated temporary or intermediate Stata datasets are not required as source inputs and are regenerated by the R workflow.

This follows the project rule: start from the same level of data used by the authors' official workflow and keep only the smallest source-data set needed to reproduce it.

## Running the replication

From R:

```r
source("E:/26S2/RA/00_RA/06_TPCvIKT/code/_00_master.R")
```

The default workflow runs the fixed household-attrition specification.

The master script performs the pipeline in order:

1. configure paths and options;
2. define common helpers;
3. initialize validation checks;
4. build baseline/follow-up household and person samples;
5. build household survey modules;
6. build the individual-level dataset;
7. merge household modules and individual aggregates;
8. construct analysis-ready household variables;
9. load common analysis functions;
10. run the fixed replication analysis.

## Build diagnostics

During construction, the workflow writes:

```text
output/build_checkpoints.csv
```

This file records stage-level diagnostics such as:

- number of observations;
- baseline and follow-up observation counts;
- unique `id_1`, `cve_viv`, and `id_loc` counts;
- duplicate-key counts.

The checkpoint system was retained because it makes survey-wave loss, key corruption, and merge expansion visible at the first affected stage.

## Important implementation details

### Identifier handling

Household, locality, person, and survey identifiers are preserved as character strings.

They must not be converted to floating-point numbers because identifiers such as `id_1` can exceed the precision of an R double and may contain meaningful leading zeros.

### Legacy Stata merges

The original scripts use older Stata `merge` syntax in places where duplicate keys can occur. The R helpers reproduce the required sequential duplicate-key behavior rather than using an unrestricted many-to-many Cartesian join.

### Stata missing-value semantics

The translation explicitly distinguishes Stata-style missing values from ordinary R logical filtering.

In particular:

- string missing values such as `""` are treated as missing where the Stata code does so;
- a Stata `replace ... if condition` does not modify observations where the condition is missing;
- translated R assignments therefore avoid `NA` logical subscripts.

### Non-food expenditure

The R replication uses the original Stata aggregate definition:

```text
n10*
n201exp-n207exp
n301exp-n313exp
```

and therefore excludes `n208exp`, `n314exp`, and `n315exp` from `exp_nfood`.

This correction is necessary for the baseline means and no-controls aggregate consumption results to reproduce the original results.

## Main generated datasets

The pipeline regenerates intermediate and processed datasets from the raw inputs.

Key processed outputs include the household and individual analysis data used by the numbered analysis scripts.

Generated datasets are reproducibility products, not required source files.

## Main outputs

The analysis produces CSV/table outputs covering, among other items:

- baseline means;
- class attendance;
- aggregate consumption effects;
- robust aggregate consumption effects;
- Lee bounds;
- disaggregated consumption;
- PAL receipt and basket summaries;
- health and anthropometric outcomes;
- nutrition outcomes;
- selected figures.

The R output set is not a perfect one-for-one reproduction of the Stata output set. See `REPLICATION_SUMMARY.md` for the exact scope differences and remaining discrepancies.

## Known limitations

The repository is considered complete for the current replication exercise, but the following differences remain:

1. `n_class_noORG` is not reproduced correctly in the classes output.
2. Controlled `exp_total` and `exp_nfood` regressions differ from the original Stata estimates.
3. The robust controlled aggregate specification shows the same divergence.
4. Four meat/fish categories are absent from `cons_disagg_new`.
5. Some R figures and supplemental tables intentionally cover a broader or different scope than the original outputs.
6. Some original prediction tables are not reproduced.

These limitations are documented rather than hidden.

## Replication conclusion

The R implementation successfully reproduces the core data structure and the central uncontrolled cash-versus-in-kind consumption results. The strongest validation is that the no-controls food, in-kind, non-in-kind, non-food, and total expenditure estimates reproduce the original closely after correcting the non-food expenditure definition.

The remaining differences are concentrated in a small set of controlled specifications, one class-attendance output variable, and output scope. They do not indicate a general failure of the sample construction or treatment coding.

For a detailed result-by-result assessment, see `REPLICATION_SUMMARY.md`.
