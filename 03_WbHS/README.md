# 03_WBHS — What's Behind Her Smile?

R replication of the supplied Stata workflow for **Gallego, Larroulet Philippi, and Repetto, “What’s Behind Her Smile? Health, Looks, and Self-Esteem” (AEJ: Applied, 2024)**.

This folder is designed for the `ra2026-replication` repository convention: executable scripts live under `code/`, source data under `data/source/`, R-generated data under `data/processed/`, and generated results under `output/`.

## 1. Replication target

The primary target is the **authors’ supplied 2024 Stata replication workflow**, not the earlier 2018 working-paper tables.

The 2018 working paper is useful as historical context, but differences between it and the current replication package should not be treated as R-replication errors unless the R results also differ from the supplied Stata workflow.

In practice:

- **R vs. supplied 2024 Stata workflow** → replication validation.
- **2024 workflow vs. 2018 working paper** → paper/version evolution.

Do not modify the R code merely to force agreement with the 2018 working paper.

## 4. Run the replication

Open `03_WBHS.Rproj`, then run from the project root:

```r
source("code/00_master.R")
```

The master script runs:

1. data preparation;
2. Tables 1–8;
3. Appendix Tables 1–5;
4. Figure 1.

If R reports a missing package, install the package named in the error and rerun the master script. The project does not install packages automatically.

### Run stages manually


## 6. Important translation details

### Stata variable abbreviations

The Stata source uses unique-prefix abbreviations such as `cs1_mea`. R requires exact names, so the translation resolves unique prefixes to the corresponding stored variable names. This behavior is handled in `code/99_helpers.R`.

### Robust standard errors

The supplied Stata analyses use `, robust`. The R workflow uses HC1 robust covariance matrices to mirror that convention.

With many randomization-stratum indicators, `sandwich` can emit repeated warnings about hat values close to 1. These warnings are diagnostic; repeated copies generated inside permutation loops are suppressed without changing the HC1 calculation.

### Table 1 Gender row

The original Stata loop mechanically attempts a regression of `lb_genero` on `lb_genero` when computing the gender-difference p-value for the Gender row. That is a degenerate self-regression. The R table leaves this single p-value blank instead of fitting a meaningless model.

### Table 2 balance tests

The supplied Stata workflow estimates balance regressions using:

- treatment status;
- randomization-strata fixed effects; and
- robust standard errors.

The R workflow follows this specification. Therefore, balance-test p-values should be validated against the supplied Stata results rather than against p-values reported in the 2018 working paper.

### Figures

The R figure code follows the plotting ranges encoded in the supplied Stata script. Differences in tick placement or other graphical defaults are cosmetic unless they change the underlying plotted data.

### Romano–Wolf adjusted p-values

The Stata workflow uses `rwolf` with 200 repetitions, seed 456, randomization strata, controls, and baseline outcomes where applicable.

The R implementation uses a stratified treatment-label permutation stepdown analogue with the same intended number of repetitions. Because it is not the Stata `rwolf` command itself, **exact Romano–Wolf adjusted p-values should be treated as validation-pending**. Small simulation or implementation differences are possible even when coefficients, conventional robust standard errors, and samples agree.

For a quick smoke test only, the repetition counts can be reduced:

```r
Sys.setenv(WBHS_RW_REPS = 20)
Sys.setenv(WBHS_IPW_BOOT_REPS = 20)
source("code/00_master.R")
```

Use the default 200 repetitions for the intended replication run.

## 7. How to judge discrepancies

Do not use the 2018 working paper as the acceptance criterion for the R translation.

Use this order:

1. **Check sample sizes against the supplied Stata workflow/output.** They should match exactly for the same specification.
2. **Check control means and regression coefficients.** These should match Stata up to rounding/floating-point precision.
3. **Check conventional robust standard errors.** These should be extremely close when the sample and specification are identical.
4. **Check figure data.** Axis/tick differences alone are cosmetic.
5. **Check Romano–Wolf and bootstrap p-values separately.** These are simulation-based and may require dedicated validation.

If R matches the supplied 2024 Stata output but differs from the 2018 working paper, report the difference as a **working-paper-to-publication/replication-package revision**, not as an R replication failure.

## 8. Current validation status

The workflow has run end-to-end in R through data preparation, Tables 1–8, Appendix Tables 1–5, and Figure 1.

Current interpretation of the external comparison is:

- apparent FU1 sample-size differences relative to the 2018 working paper should **not** be used to alter the R sample selection;
- Table 2 p-value differences relative to the working paper should **not** be used to replace the strata-adjusted robust regressions in the supplied Stata workflow;
- substantive coefficient differences relative to the 2018 working paper should first be checked against the current Stata outputs before any R code is changed;
- graphical axis/tick differences are cosmetic when the plotted values agree;
- exact Romano–Wolf adjusted p-values remain the main item requiring dedicated Stata-vs-R validation.

## 9. Reproducibility principle

The objective of this folder is to reproduce the **authors’ current replication workflow in R** as faithfully as possible. Historical working-paper values are documented when useful, but the R implementation should not be reverse-engineered to reproduce obsolete values when those values differ from the supplied replication code.
